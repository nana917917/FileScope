# FileScope 5.1.0-rc2 changes

This RC builds on 5.1.0-rc1. It keeps the Tkinter interface, local index,
bounded search workers, lazy preview, optional OCR, and existing file readers.

## Changes

- Search 2 is now combined with Search 1 using AND and runs through the normal
  indexed/direct search pipeline over the same folders. The screen says so,
  shows normal progress and coverage, and supports Search 2 alone. Saved
  presets keep Search 2; recent search history stores the exact combined query.
- Fixed the previous result-refine behavior. It only inspected capped displayed
  evidence and could not reliably prove a miss. Search 2 now reads/indexes the
  corpus under the normal completeness rules.
- A `2of(...)` result shows matching candidates and the count. If the search
  stopped early after meeting the threshold, other candidates are marked
  `未確認`; they are called `未一致` only after the file was fully read. For
  example: `一致:耐久、振動 / 未確認:温度（2/3以上）`.
- Result column widths and the result/preview split are restored on next start.
- Added safe startup phase timings to the local log (UI module import, stale
  temporary-file cleanup, OCR probe, index open, first Tk idle). These records
  contain durations only; no query or document contents.
- Added product research, search design decision, and source links in
  `docs/research/UX_BENCHMARK.md`.

## Search 2 design

Two independent search result sets would require users to choose which scope
Search 2 searches and how the two result sets combine. The adopted model is a
second condition, ANDed with Search 1. The app reruns the normal search over the
same roots. This may take longer than a visual filter, but results remain
consistent with direct/index behavior and the existing progress, cancellation,
cloud policy, and issue reporting.
