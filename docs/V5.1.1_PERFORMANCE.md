# FileScope v5.1.1 性能確認（UI変更が速度を落としていないか）

測定日: 2026-10-13 / 同一PC（i7-11700K, 8C/16T, 17 GB）/ Python 3.11.9
比較: v5.1.0 チェックアウト（タグ `v5.1.0` = `eac9089` のworktree）と
v5.1.1 候補（`codex/v5.1.1-ui-polish`）。同一コーパス・同一索引・同一設定。

今回の変更は画面のレイアウト・余白・区切り線・状態表示のみで、検索経路
（`SearchSession`、索引、`_index_lock`）には触れていません。その前提が
実際に守られているかを確認するための測定です。

## 1. 索引検索（2,000ファイル、索引済み、標準モード、ワーカー4、3回の中央値）

| 指標 | v5.1.0 | v5.1.1候補 | 差 |
| --- | ---: | ---: | ---: |
| 検索時間（実時間） | 0.607 s | 0.499 s | -18%（実行ごとのばらつき範囲内） |
| 検索時間（CPU時間） | 0.813 s | 0.578 s | 同一〜やや軽い |
| パイプラインの初回ヒット | 16.5 ms | 29.1 ms | この指標は数ms〜数十msで揺れるため同等と判断 |

## 2. GUI経由（2,000ファイル、索引済み、実際のTkウィンドウで駆動）

| 指標 | v5.1.0 | v5.1.1候補 |
| --- | ---: | ---: |
| 検索完了まで | 0.572 s | 0.514 s |
| 1件目が一覧に出るまで | 0.137 s | 0.133 s |
| 一覧の再構築回数 | 3 | 3 |
| 一覧再構築の合計時間 | 0.029 s | 0.026 s |
| UIスレッドの最長停止 | 62 ms | 61 ms |

## 3. 起動（ソース版、リダイレクトしたLOCALAPPDATAで1回ずつ）

| 指標 | v5.1.0 | v5.1.1候補 |
| --- | ---: | ---: |
| `first_ui_idle` | 0.351 s | 0.356 s |
| UI import | 0.084 s | 0.090 s |
| OCR probe | 0.066 s | 0.068 s |

## 4. 判断

いずれも差は実行ごとのばらつき（1桁〜2桁ms、または同一値）の範囲で、
UI変更による速度・起動・メモリの悪化は確認できませんでした。索引検索の
高速化（v5.1.0）はそのまま維持されています。

## 5. 未検証

- Office/PDF中心の実コーパス（本測定は生成テキストコーパス）
- 凍結版（EXE）での性能。候補ZIPのビルドと実行確認は別途行います。
- 125% / 150% の表示倍率
