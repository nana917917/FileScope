# FileScope UI方式の再評価

次期候補はTkライト版（案B）。配布候補でFileScope.exeを起動するとTkライト版が表示される。Qtの比較画面はFileScope.exe --qt-uiで起動できる。

基準はQt候補 ab467f8、Tk改善版 e24d9a4、正式版 v5.1.1（コミット4c11e4e）。既存ブランチに加えて codex/ui-performance-review を使用。アプリの検索処理とSQLite形式は既存のものを共有する。

## ネイティブWindowsでの計測

scripts/perf_event_loop.py はTk mainloopとQt app.execを使用する。合成テキスト1万件、索引OFF、1,260×790、全件一致、各3回。タイマー間隔は40 msの周期を含む。表は各実行の指標の中央値。

| 指標 | Tk改善版 | Tkライト | Qt |
| --- | ---: | ---: | ---: |
| ソース起動から検索ボタン呼び出しまで | 721 ms | 616 ms | 1,160 ms |
| 検索開始から画面完了 | 3.78 s | 3.86 s | 4.73 s |
| タイマー間隔 p50 | 46.9 ms | 46.8 ms | 231 ms |
| タイマー間隔 p95 | 67.2 ms | 68.2 ms | 299 ms |
| タイマー間隔 最大 | 90.5 ms | 84.7 ms | 335 ms |
| CPU時間 | 7.02 s | 7.09 s | 7.48 s |
| ピークワーキングセット | 66.5 MiB | 66.2 MiB | 99.6 MiB |

単発の選択操作では、Tkライトのスクロール呼び出し約19.5 ms、行選択約1.5 ms、プレビュー約192 ms。Qtは約3.0 ms、9.2 ms、520 ms。描画完了時刻ではなく、スクロールと選択は呼び出し時間、プレビューはキャッシュ反映をタイマーから観測した時間。中断の単発観測はTk約160 ms、Qt約90 ms。これらは実マウス操作の計測ではない。

ヒット密度を変えた1回ずつの追試では、1件でp95がTk 51.7 ms / Qt 61.0 ms、300件で52.7 / 53.4 ms、1,000件で53.0 / 62.0 ms。1,000ヒット条件で索引を有効にし、既存の索引を利用する2回目は完了まで1.29 / 2.30秒、p95は60.2 / 55.0 ms。初回の索引作成を含む検索はどちらも約50秒。

## Qtの内訳と試行

- ソートなしの計測では比較関数0回、フィルター1万回で合計約8 ms、行追加通知の最大約32 ms、イベント取り出しの最大約34 ms。p95約280 msの大部分はそれらの外にある。data()は約1.38万回・合計約259 ms。描画やQt/Python間の呼び出し、検索中の競合の内訳は未分離。
- ファイル名の列ソートを有効にすると、元の比較関数は約8.2万回、キー計算は約16.4万回。beginInsertRowsの合計は約1 msだが、endInsertRowsは合計約4.19秒、最大約864 msで、検索結果を取り込む処理と重なる。
- 比較キーを行単位で再利用した単発試行では、キー計算の計測合計は592 msから236 ms、行追加通知の最大は864 msから702 msへ低下。ソート中のp95は約890 msでほぼ同じ。更新行のキャッシュは破棄する。dynamicSortFilterのみを切る試行でも新規行の比較が残ったので常用設定にはしなかった。
- Qtの起動内訳の無ソート計測例は設定・計測準備約81 ms、UI import約147 ms、QApplication約32 ms、テーマ込みウィンドウ構築約432 ms、その後の最初の描画まで約347 ms。テーマ適用の計測は約355 ms（構築に含む）。OCR・索引の重い処理は初回起動の内訳に含まれない。PyInstallerの内訳と真のコールド起動は未分離。

## UIと使い方

Tkライトでは白背景、キャッシュ済みの種別アイコン、ファイル名を優先した列幅、対象形式・メンテナンスのメニューを用意した。通常の索引管理、診断、結果操作は既存Tk画面にある。プレビューとPDF画像の導線を維持した。

約4万文字・9,900箇所一致の合成プレビューで、Tkの描画呼び出しを約233 msから約26 msに短縮した。修正前は1回、修正後は3回の中央値。クリック後の本文抽出は含まない。検索結果のHit数とは独立して、プレビューとその移動対象を1,000件に制限し、画面に明記した。

Tkの条件作成では既存の条件を読み込み、候補語数と必要一致数を表示する。Qtでは単独の単純なN-of式を「既存の指定数条件を編集する」から変更できる。それ以外の入力済みの式はテキスト欄に保持し、追加条件を別に入力する。検索2の意味は同じ。

最大級の実文書、SMB、コールドスタート、手操作の遅延は未確認。Qtの索引・診断専用画面は未追加。比較ZIPは両方のランタイムを収録するため、Tk単独配布時のサイズには相当しない。
