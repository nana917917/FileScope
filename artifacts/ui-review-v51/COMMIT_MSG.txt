fix(search): quoted conditions and many-condition hangs; 4x faster matcher

Two user-reported defects, reproduced and fixed:

1. The condition builder never parsed the existing expression: it dropped the
   whole query into the first field as one literal, so "AAA&BBB" became the
   phrase "AAA&BBB" and a quoted phrase became a phrase containing quotes -
   both matched nothing. Quoted values typed into a field had the same
   problem. The builder now parses the incoming query into its fields
   (parse_into_groups), strips surrounding quotes from field values
   (clean_literal), escapes backslashes correctly, and keeps anything it cannot
   express in a collapsed detail box so the meaning survives a round trip
   (query.equivalent() asserts it).

2. A pathological expression (deep nesting) raised RecursionError, which
   SearchSession.start() did not catch, leaving the UI in the searching state.
   parse_query now rejects over-long/over-nested input with a normal query
   error, and start() converts any unexpected failure into a QueryFailed event.

Performance: the per-chunk scan is grouped by first character, already-found
terms are not rescanned for JIT queries, and the AST is only re-evaluated when
a chunk actually added information. 100 conditions over 2000 chunks: 164ms ->
39ms. Direct/Index equivalence and the V4.1 compatibility suite stay green.

64 new tests (quotes, builder round trip, 10/30/50/100 conditions, deep
nesting, scan-plan brute-force comparison).
