# FileScope v5.1.1 変更点

基準: v5.1.0 (`eac9089`) / 作業ブランチ: `codex/v5.1.1-ui-polish`

**検索式の意味・検索対象・索引と直接検索の一致という仕様は維持しています。**
画面の見た目と操作性を、実際の画面（`artifacts/ui-review-v511/` の実ウィンドウ撮影）で
確認しながら直しました。あわせて、独立レビューで見つかった**検索漏れと索引ロック中の待機の不具合**を
修正しています（§7）。検索の「仕様」は同じですが、検索処理のコードには手を入れています。

## 1. 主な操作が分かるようにした

| 変更 | 内容 |
| --- | --- |
| 検索開始を目立たせる | 唯一のアクセント色ボタンにしました（既存のOCR強調色 `#1f5f8b` と同じ色。新しい色は増やしていません） |
| 行の高さ・間隔の統一 | 全ボタンに同じ余白（`padding=(9,4)`）と行間（5px）を与え、入力欄・ラベル・ボタンの高さと位置をそろえました |
| 区切り線 | 「検索場所・検索文字・除外」と「モード・検索対象」の間、および結果一覧の直前に横罫線を入れました |
| 補助ボタンの整理 | 条件…／詳細設定…／索引…／診断… を検索対象の右側にまとめ、縦罫線で対象チェックと区切りました。よく使う `条件…` は先頭のまま、実行系（中断／一時停止）とライブラリ系（プリセット／履歴）も縦罫線で分けました |
| 一覧とプレビューの境界 | プレビュー側に1pxの境界線を付けました（サッシのドラッグ操作は従来どおり） |
| 状態表示 | 完了時は `完了: 6資料 / 12件一致 / 0.2秒`、中断時は `中断: 6資料 / 0.2秒`。自動保存はファイル名だけを表示し、小さい画面でも右側の表示が切れなくなりました |

## 2. 変えていないもの（検索仕様・既存機能）

- 検索式・条件ビルダー・Search 1 / Search 2・2of の一致語表示
- 検索結果・索引・設定ファイルの形式、ショートカット、CSV保存、プレビューの動作
- 検索の高速化（v5.1.0 の `_index_lock` ほか）と起動経路の設計
- Tkinter のまま。新しいUIフレームワークや依存ライブラリは追加していません

検索処理のコードは2か所だけ変更しました（`pattern_id` の一意化、索引ロック中の
結果公開の分離）。どちらも**結果を失わない／待たせない方向の修正**で、検索結果の
意味は変わりません（§7と `docs/V5.1.1_REVIEW.md`）。

## 7. 独立レビューで見つかった修正（UI以外）

独立レビューの **FAIL 判定は v5.1.0 に対するもの**で、指摘の主要部分は本版で修正しました。
詳細は `docs/V5.1.1_REVIEW.md` を参照してください。

1. **検索漏れ（P1）**: `part_number_mode` で記号始まりの語（`_A0009B` など）が
   `pattern_id` の衝突により黙って一致しなくなる不具合。v5.1.0 に含まれ、v5.0.0 には
   ありません。単調増加カウンタに変更しました。
2. **索引ロック中の結果公開（P3）**: イベントキューが満杯のときに索引レーン全体が
   待たされる問題。判定と公開を分離しました。

### 修正の確認（2026-10-13）

| 確認 | v5.1.0 | v5.1.1 |
| --- | ---: | ---: |
| 400個のコンパイル済みパターンでの `pattern_id` 重複 | 144 | **0** |
| `2of(_A0091B, _A0092B)` と本文 `_A0091B _A0092B` の一致語 | `_A0091B` のみ（1語が欠落） | 両方一致 |

さらに、記号始まりの語だけを含む小さなコーパス（4ファイル）で `part_number_mode` を
有効にして、`2of(_A0009B, _A0010B)`・`_A0009B`・記号始まり10語のAND を実行し、
**ソース版と候補版EXEの結果が完全一致**し、期待するファイルが欠落しないことを
確認しました。重複idの有無は `scripts/check_pattern_ids.py <チェックアウト>` で
再確認できます（v5.1.0で重複あり／v5.1.1で0）。
