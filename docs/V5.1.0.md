# FileScope 5.1.0 リリースノート（日本語）

基準: v5.0.0 (`58b9e9e`) / 作業ブランチ: `codex/v5.1-ux-performance`
前回配布: 5.1.0-rc2 (`dist/rc2/FileScope-v5.1.0-rc2-win64.zip`)

v5.1 の変更点は `docs/V5.1_CHANGES.md`（rc1）と `docs/V5.1.0-rc2.md`（rc2）に
書いてあります。ここには **rc2 以降に実機フィードバックを受けて行った調査と修正**、
および正式版の検証結果をまとめます。

## 1. 今回の調査でわかったこと

「検索中が前のバージョンより少し重い」という実機の感想を受け、検索を段階ごとに
計測しました（列挙 / 属性取得 / 索引参照 / 内容抽出 / マッチ / 結果生成 / GUI反映 /
進捗更新 / キャンセル）。調査結果の詳細と生データは `docs/performance/V5.1.0.md` と
`docs/performance/raw/v5.1.0/` にあります。

**原因は検索そのものではなく、索引検索でのスレッドの使い方でした。**

索引から答えられるファイルの処理は、Python と sqlite3 の行取得だけで、GIL により
並列化できません。それなのに既定の4ワーカーで同時に走らせていたため、お互いを
遅くしていました（CPU時間は1ワーカーの約5倍、実時間は約3倍）。

| 10,000ファイル・索引済み・標準モード | 修正前 | 修正後 |
| --- | ---: | ---: |
| ワーカー1（実時間 / CPU） | 2.96 s / 3.66 s | 2.81 s / 3.55 s |
| ワーカー4（既定） | **9.50 s / 15.86 s** | **3.60 s / 4.32 s** |

2,000ファイルでも同じ傾向です（既定ワーカーで 2.10 s → 0.67 s、Search 1 + Search 2 は
2.51 s → 0.85 s）。1ワーカーの所要時間は変わっていないため、検索能力や検索対象を
犠牲にした高速化ではありません。

## 2. 修正内容

1. **索引参照の直列化** — 索引からの判定（差分確認・判定）を1つのロックで直列化し、
   内容抽出は従来どおりワーカーを並列で使います。結果は変わりません
   （ワーカー数を1/2/4/8と変えても同じ結果になることをテストで固定）。
2. **保存済み本文の読み出しを軽量化** — 索引からの行読み出しで行っていた
   毎行の enum 変換・try/except を辞書参照と型チェックに置き換えました。
3. **進捗と一覧更新の分離** — 検索中は100 msごとに状態を更新しつつ、一覧の再構築は
   400 msまで間引きます。進捗・カウンタはこまめに、重い一覧更新は控えめに動きます。
4. **最初の結果を早く表示** — 検索開始直後に一度UIを更新し、検索中は間隔を詰めました。
   1件目が出るまでの体感が 0.20→0.11 秒程度になります（実測）。
5. **検索中に選んだ行とプレビューを保持** — 一覧を再構築しても、プレビュー中の行の
   選択とプレビュー内容が消えなくなりました（従来は検索中に2秒ごとに選択が外れ、
   プレビューが空になっていました）。同じファイルを選び直しても再読み込みしません。

検索式（AND / OR / NOT / 2of / NEAR / 引用符 / 括弧）、条件ビルダー、Search 1 /
Search 2、2of の一致語表示、設定保存、PDFページ画像、OCR、SMB、OneDrive の扱いは
変更していません。

## 5. 未検証の項目

この環境では確認できなかった項目です。**検証済みとして扱っていません。**

- 実際の Tesseract OCR（本機に未導入。通常のPDF・Office・テキスト検索は可）
- 実際の SMB 共有、OneDrive / SharePoint のオンライン専用ファイル
- ネイティブウィンドウを自動化セッションから操作できないため、
  指定サイズ（1024x640 / 1280x720 / 1920x1080）・表示倍率（100/125/150%）での
  目視監査。Tkの統合テストは代替になりません。
- 実機のOffice/PDF中心コーパスでの速度。今回の計測は生成したテキスト
  コーパス（2,000件 / 10,000件）によるものです。

## 6. 判断

重大な検索不具合・性能回帰は確認できませんでした。検索結果は修正前後で同一で、
既定の4ワーカーでの索引検索が2,000件/10,000件で約2.6〜3.1倍速くなっています
（単一ワーカーの所要時間は不変）。上記の未検証項目はありますが、ユーザーの実機で
基本操作に問題がないこと、自動テスト・配布版確認・独立レビューが通っていることを
踏まえ、**GO** と判断し v5.1.0 を正式リリースします。
