# FileScope V5.1.0-rc2 performance record

Measured 2026-10-13 on the same Windows host, Python 3.11.9, same generated
corpus and settings, using the RC1 commit `3e5de6d` and RC2 working tree. Each
2,000- and 10,000-file scenario ran three times. This corpus contains generated
text files; it is not a representative Office/PDF, network, OCR or cloud test.
Times are medians unless a sample list is shown. The raw runs are in `raw/`,
with computed medians in `aggregate.json`.

## Search comparison

| Scenario | RC1 median | RC2 median | Change |
| --- | ---: | ---: | ---: |
| First result, 2,000 files | 12.4 ms | 7.0 ms | -43.5% |
| Direct full search, 2,000 files | 0.663 s | 0.639 s | -3.6% |
| Index build, 2,000 files | 8.572 s | 8.353 s | -2.6% |
| Indexed repeat, 2,000 files | 1.960 s | 1.996 s | +1.8% |
| Japanese 2-character index search, 2,000 files | 1.899 s | 1.867 s | -1.7% |
| Selective index search, 2,000 files | 0.560 s | 0.557 s | -0.5% |
| First result, 10,000 files | 6.1 ms | 7.2 ms | +18.0% (+1.1 ms) |
| Direct full search, 10,000 files | 3.600 s | 3.713 s | +3.1% |
| Index build, 10,000 files | 46.196 s | 46.063 s | -0.3% |
| Indexed repeat, 10,000 files | 10.480 s | 10.085 s | -3.8% |
| Japanese 2-character index search, 10,000 files | 9.608 s | 9.652 s | +0.5% |
| Selective index search, 10,000 files | 2.954 s | 2.921 s | -1.1% |

The first-result difference at 10,000 files is 1.1 ms and varies within a
single-digit millisecond range. The full direct search is 3.1% slower at that
size. Neither result shows a material regression, but the data does **not** show
a broad search-speed improvement. Search 2 adds an AND expression and performs
a fresh, correctly scoped search; its total time depends on the combined query.

In the first of three 10,000-file direct runs, both versions were much slower
(RC1 3.518 s, RC2 14.781 s for the first run). The following runs were RC1
3.600/3.641 s and RC2 3.713/3.615 s. The first-run outlier indicates a cold
system cache or host load; the median is shown, and cold and warm runs are not
claimed to be interchangeable.

## Matching stress and memory

The 100-condition / 2,000-chunk matcher was measured five times per version,
including query parsing and matcher construction:

| Version | Samples | Median |
| --- | --- | ---: |
| RC1 | 34.01, 35.05, 36.60, 37.28, 43.79 ms | 36.60 ms |
| RC2 | 37.22, 35.82, 35.59, 38.41, 39.18 ms | 37.22 ms |

This is a 1.7% difference. All runs reached the same reject result. 2,000-file
peak working set medians were 92.35 MB (RC1) and 92.999 MB (RC2); 10,000-file
medians were 83.59 MB and 84.06 MB. Sampling and OS cache effects are larger
than these differences. The persistent index was about 24.7 MB at 2,000 files
and about 110–115 MB at 10,000 files.

## GUI startup

Three source-mode launches used isolated `LOCALAPPDATA`, opened the actual
Tkinter main window, reached the first idle callback, then closed through
`MainWindow.on_close()` after a short measured interval:

| Version | First-idle samples | Median |
| --- | --- | ---: |
| RC1 | 400.8, 208.3, 204.1 ms | 208.3 ms |
| RC2 | 299.5, 215.2, 226.2 ms | 226.2 ms |

RC2's median is 8.6% slower (17.9 ms), with its first cold run 101 ms faster.
The benchmark starts its clock immediately before `run_gui`; Python interpreter
startup and module imports before that point are excluded. No frozen EXE startup
comparison was possible without a new bundle. RC2 logs UI import, temporary
cleanup, OCR probe, index open and first idle timings locally. Three measured
RC2 runs showed UI import 0–57 ms, cleanup 0–3 ms, OCR probe 45–61 ms, and index
open 5–13 ms. No query or document text is written to these performance logs.

## Unmeasured or blocked scenarios

- The benchmark does not measure progress-queue responsiveness under real slow
  Office, SMB or OCR files, nor cancellation timing under those conditions.
- Tesseract is absent on this host. Actual OCR and its cancellation/resource
  behavior were not verified.
- The desktop automation inventory exposed no native apps/windows, so visual
  screenshots at 1024x640, 1280x720 and 1920x1080 and 100/125/150% display
  scaling could not be captured or reviewed. Tkinter GUI integration tests did
  run, but they are not a visual audit.
- The benchmark proves the search pipeline timings on synthetic text only; it
  does not prove portable-package startup until the RC2 build is inspected.
