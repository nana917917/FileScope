# FileScope v5.1 変更点（RC）

基準: v5.0.0 (`58b9e9e`) / 作業ブランチ: `codex/v5.1-ui-stability` / バージョン: `5.1.0-rc1`

今回の目的は「検索能力は高いのに、見た目が未完成で操作中に不安になる」状態の解消です。
新しい検索機能は追加していません。

## 1. 修正した不具合（ユーザー報告）

### 1-1. 引用符 `"` が付くと検索できない

**症状**: 条件ビルダーで条件を入れると `""` が付いた式になり、何もヒットしない。

**原因（再現済み）**: 条件ビルダーが既存の検索式を**解析せず**、全文を「すべて含む」欄の
1語として扱っていました。そのため

| 入力 | v5.0.0 が作った式 | 結果 |
| --- | --- | --- |
| `AAA&BBB` | `"AAA&BBB"`（1つのリテラル） | 0件 |
| `"耐久 試験"` | `"\"耐久 試験\""`（引用符を含むフレーズ） | 0件 |
| 欄に `"ABC-123"` と入力 | `"\"ABC-123\""` | 0件 |

パーサ自体は `"AAA"` `"耐久 試験"` `2of("A","B","C")` `"ABC-123"` など正しく解釈していたため、
原因はビルダー側の往復変換にありました。

**修正**:

* 開いたときに既存の式を解析して各欄へ分解（`parse_into_groups`）
* 欄の値の囲み引用符を外す（`clean_literal`。`"` `“ ”` `「 」` に対応）
* バックスラッシュのエスケープを往復で一致させる
* 欄で表現できない式は「詳細式」欄にそのまま保持
* 生成式が元と**同じ意味**かテストで検証（`query.equivalent`）

### 1-2. 条件を多数入れると検索されなくなる

**症状**: 条件を増やすと検索が固まる／動かなくなる。

**原因（2つ）**:

1. 極端に入れ子の深い式（例: 括弧400段）で `RecursionError` が発生し、
   `SearchSession.start()` が `QuerySyntaxError` しか捕捉していなかったため、
   UIが「検索中」のまま復帰しない（＝無反応に見える）。
2. 条件数に比例して1チャンクあたりのAST評価が重くなる。
   100条件×2000チャンクで **164ms/ファイル**。

**修正**:

* `parse_query` が長すぎる式・深すぎる括弧を通常の検索式エラーとして返す
* `start()` は予期しない例外も `QueryFailed` に変換し、UIのボタンを必ず復帰させる
* 1文字目ごとのグループ化、JITでの既出語スキップ、情報が増えた時だけのAST再評価

**結果**: 100条件×2000チャンクで **164ms → 39ms（約4.2倍）**。
10/30/50/100条件の検索が正しく動作することをテストで固定。

## 2. UI・操作性の改善

### 2-1. レイアウト（最優先）

* 検索場所・検索文字・除外欄が**ウィンドウ幅いっぱい**に伸びるようにした（grid weight）
* 検索場所の右に `参照` / `＋追加` / `一覧` を配置
* 検索文字の右に `検索開始` を配置（探しやすくした）
* ウィンドウを広げると結果一覧とプレビューが自然に広がる（サッシュはドラッグで変更可、
  プレビュー幅が0になる不具合は再発防止済み）

### 2-2. フォントと文字

* 画面全体で1つのUIフォント（Windows標準の日本語UIフォント）に統一
* 本文9pt、検索入力のみ10pt。大きな等幅フォントは廃止
* 太字は欄の見出しと重要な状態のみ

### 2-3. 検索モードの説明

選ぶと1行の説明が表示されます。高速モードの制限（未索引・オンライン専用は対象外）も明記。

### 2-4. 複数フォルダ

* `＋追加` は既存の指定を消さずに追加、重複は拒否
* `一覧` で確認・削除・並べ替え。存在しないパスは赤字で表示
* `;` 区切りの手入力も従来どおり動作（後方互換）

### 2-5. 進捗表示

* 進捗バーはフォルダ確認中は**不定**、総数確定後に**%表示**へ切替（偽の割合は出さない）
* 処理中のファイル名・フェーズ（フォルダ確認／検索／PDF読み取り／索引確認）を表示
* 1ファイルに時間がかかると「処理に時間がかかっています」と表示（停止とは断定しない）
* 結果件数は「結果をさらに絞る」の横、カバレッジは別行に分離して二重表示を解消

### 2-6. プレビュー

* ファイル名を見出しに、種類・サイズ・ページ数・フォルダ・一致語を1行で表示
* 本文は読みやすい等幅フォント、場所ラベル（セル番地・ページ・段落）と一致語をハイライト
* 「前の一致 / 次の一致」で移動

### 2-7. PDFページ画像プレビュー（新規）

* プレビューに `文字` / `画像` 切替、ページ移動、拡大縮小（50〜200%）を追加
* 選択したPDFの該当ページだけを描画（最大1200万画素、3ページまでキャッシュ）
* **オンライン専用PDFは検索時の取得ポリシーに従い、勝手に取得しない**
* 検索中のPDFは画像化しない（選択したときだけ）

| Direct検索（2,000ファイル） | 2.064 s | 2.138 s | +3.6% |

## 5. 検索結果の互換性

* Direct/Index一致テスト（20条件）と V4.1互換テスト（30ケース）は変更なしでPASS
* 既存の設定ファイル・索引はそのまま読めます（v5.0.0 → v5.1で索引形式は不変）
* ヒット件数の表示は、JITで読み込みを止めた場合に従来どおり下限 `8+` 表示のまま

## 6. 既知の制約・今回見送ったもの

* PDF画像プレビューは**該当ページの表示のみ**（PDFビューアとしての連続スクロールや検索は対象外）
* 高速モードは索引に無い資料を検索しません（説明文に明記）
* 1〜2文字の語は索引ではなくキャッシュ本文の走査（従来どおり）
* Tesseract未導入環境ではスキャンPDFの文字は検索できません（通常検索は可）
* PySide6・CustomTkinter等への移行は行っていません（Tkinterのまま、配布サイズ増ゼロを優先）

## 7. 実機で確認していただきたい点（追加分）

`docs/LOCAL_ACCEPTANCE_TEST.md` の A〜G に加えて、v5.1では次を確認してください。

1. ウィンドウを最大化／縮小しても、検索場所・検索文字の欄が幅いっぱいに伸びること
2. 文字サイズと太字が自然で、情報量が増えていないこと
3. 検索モードを切り替えると説明文が変わること
4. `＋追加` で複数フォルダを指定し、`一覧` で削除できること
5. 検索中に進捗バーと「処理中: ファイル名」が出て、総数確定後に%へ変わること
6. 条件ビルダーで条件を作り、OK → もう一度開いても条件が壊れていないこと
7. 引用符付きの語（例 `"ABC-123"`）で検索できること
8. PDFを選び「画像」ボタンで該当ページが表示され、ページ移動・拡大縮小ができること
9. 検索結果の件数がv5.0.0と同じであること（同じ検索条件で比較）
